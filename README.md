# Chuko Stock

Plataforma web orientada a la comercialización y gestión de prendas textiles, con el objetivo de digitalizar un emprendimiento artesanal y profesionalizar la administración de su inventario y ventas.

## Descripción

**Chuko Stock** nace a partir de la identificación de una oportunidad de negocio dentro del sector textil artesanal.

El emprendimiento, que opera de manera informal desde hace aproximadamente dos años, se especializa en el diseño y confección de prendas tejidas, tanto de forma manual como mediante procesos mecánicos, con un enfoque en prendas de alta gama.

El público objetivo está compuesto principalmente por mujeres de nivel socioeconómico medio-alto y alto, residentes en urbanizaciones cerradas (*countries*) del Gran Buenos Aires.

El proyecto busca digitalizar este modelo de negocio mediante una plataforma que permita gestionar el inventario de piezas únicas, facilitar la comercialización y centralizar la información de productos y vendedores.

De esta manera, se busca pasar de una gestión basada principalmente en contactos personales a un sistema digital más organizado, eficiente y escalable.

## Nombre e identidad visual

### ¿Por qué "Chuko Stock"?

El nombre **Chuko Stock** surge de la combinación de dos conceptos:

* **Chuko (中古):** término japonés relacionado con objetos usados o de segunda mano.
* **Stock:** hace referencia a la cantidad y variedad de prendas disponibles dentro de la plataforma.

El nombre busca representar la idea de un catálogo amplio de prendas, incluyendo piezas originales que pueden ser difíciles de encontrar en otros lugares.

### Logo

La identidad visual del proyecto está inspirada en la cultura japonesa.

El logotipo fue creado inicialmente utilizando una tipografía de estilo japonés llamada **"JAPAN RAMEN"**.

Posteriormente, se utilizó inteligencia artificial para adaptar el diseño a la identidad visual buscada.

**Prompt utilizado:**

# Análisis FODA

El análisis FODA permite identificar los factores internos y externos que pueden influir en el desarrollo del proyecto.

## Fortalezas

* Trabajo en equipo.
* Precios accesibles.
* Accesibilidad a un público amplio.
* Las prendas son tasadas por el propio equipo.
* Posibilidad de encontrar prendas originales que ya no se consiguen fácilmente.

## Debilidades

* Falta de disciplina.
* Tiempo limitado para desarrollar y gestionar el proyecto.
* Dificultad para conseguir prendas en buen estado.
* Poco personal disponible.

## Oportunidades

* Posibilidad de acceder a un mercado amplio.
* Idea innovadora dentro del mercado.
* Posibilidad de utilizar la plataforma tanto por personas particulares como por empresas.
* La propuesta innovadora puede atraer a personas interesadas en trabajar o colaborar con el proyecto.

## Amenazas

* Mala gestión de la calidad de las prendas o publicaciones.
* Publicaciones incorrectas o de baja calidad.
* Falta de moderación dentro de la plataforma.

# Manejo de publicaciones, reglas y pautas

Para mantener la calidad y confiabilidad de la plataforma, será necesario establecer reglas y pautas para la publicación de productos.

Algunas de las medidas consideradas incluyen:

* Establecer requisitos mínimos para publicar una prenda.
* Definir criterios de calidad para las imágenes y descripciones.
* Implementar mecanismos de moderación.
* Establecer reglas para vendedores y compradores.
* Implementar medidas de control para evitar publicaciones incorrectas.
* Mantener un sistema organizado para gestionar posibles conflictos.

Estas medidas permitirán mantener un entorno estable y confiable para los usuarios de la plataforma.

# Análisis preliminar

## 10 usos indispensables de la aplicación

**Autores:** Carrizo, Huarachi y Rolones.

### 1. Carrito de compras

Los usuarios podrán agregar productos al carrito y visualizar el costo total de su compra antes de realizarla.

### 2. Sistema de registro

Los usuarios deberán registrarse en la plataforma para poder realizar compras.

El sistema de registro permitirá crear una cuenta y asociar la actividad del usuario a su perfil.

### 3. Filtros de búsqueda

La plataforma contará con filtros que permitan realizar búsquedas más específicas dentro del catálogo.

Los usuarios podrán utilizar diferentes criterios para encontrar las prendas que buscan de manera más rápida.

### 4. Lista de deseos

Cada usuario podrá disponer de una lista personal donde guardar las prendas del catálogo que sean de su interés.

Esto permitirá consultar posteriormente los productos seleccionados sin necesidad de buscarlos nuevamente.

### 5. Verificación durante el registro

Durante el registro se plantea solicitar el **Documento Nacional de Identidad (DNI)** argentino.

El objetivo planteado originalmente es verificar que los usuarios pertenezcan al país donde opera la empresa.

> **Nota:** La implementación real de esta función requeriría considerar aspectos de privacidad, protección de datos y seguridad antes de almacenar o procesar documentos de identidad.

### 6. Suscripción a un Newsletter

Los usuarios podrán suscribirse a un boletín de novedades (*Newsletter*) para recibir información sobre ofertas, nuevos productos y otras novedades de la plataforma mediante correo electrónico.

### 7. Perfiles de vendedores

Cada vendedor contará con un perfil público.

Esto permitirá que otros usuarios puedan consultar información relacionada con el vendedor antes de realizar una operación.

### 8. Lista de tendencias

La plataforma contará con una sección donde se puedan visualizar las prendas que presentan mayor cantidad de interacciones, clics o ventas.

Esto permitirá identificar cuáles son los productos que generan mayor interés entre los usuarios.

### 9. Recuperación de cuenta

En caso de que un usuario pierda su contraseña, podrá iniciar un proceso de recuperación de cuenta mediante su correo electrónico.

El sistema permitirá restablecer el acceso de manera segura.

### 10. Ayuda al cliente

La plataforma contará con un apartado de atención al cliente.

Los usuarios podrán utilizarlo para consultar problemas relacionados con la plataforma, realizar consultas sobre operaciones o enviar sugerencias para futuras mejoras.

# Puesta en marcha (XAMPP)

**Requisitos:** XAMPP con Apache + MySQL/MariaDB y PHP 8.0 o superior.

1. Copiá esta carpeta a `C:\xampp\htdocs\chukostock` (o `/opt/lampp/htdocs/chukostock`).
2. Encendé **Apache** y **MySQL** desde el panel de XAMPP.
3. Base de datos:
   * **Si ya tenés la base `chukostock` en tu XAMPP**, no importes nada: la app usa esas mismas tablas.
   * **Base nueva:** en phpMyAdmin → *Importar* → `sql/schema.sql` y después `sql/datos_iniciales.sql` (categorías y marcas).
4. Copiá `config.local.php.example` a `config.local.php` y completá usuario/clave de MySQL y los emails de los empleados (`MODERADORES`).
5. Abrí <http://localhost/chukostock/>.

> Las cuentas de ejemplo que ya existían en la base guardan su contraseña con `password_hash` (bcrypt), la app las reconoce igual, pero hace falta saber la contraseña original. Si no la sabés, creá una cuenta nueva desde *Crear cuenta*.

## Decisiones por lo que la base de datos tiene (y no tiene)

* **Sin tabla de carrito** → el carrito vive en la sesión del navegador.
* **Sin tabla de newsletter ni de consultas de ayuda** → se quitaron los formularios de newsletter y de consultas; *Ayuda* muestra preguntas frecuentes y, si se define `EMAIL_AYUDA`, un contacto.
* **Sin tokens de recuperación** → no se envían emails: se restablece la contraseña confirmando **email + DNI** de la cuenta.
* **Sin columna de rol** → los empleados (moderación/pedidos) se definen por email en `MODERADORES` de la configuración.
* **Sin contador de visitas** → *Tendencias* se calcula con deseados y ventas.
* **`usuario.ID_Usuario` no es AUTO_INCREMENT** en la base original → la app calcula `MAX + 1`. Funciona igual si más adelante lo hacés AUTO_INCREMENT.
* **`usuario.Telefono` es `INT UNSIGNED`** (máx. 4.294.967.295) → se aceptan teléfonos de hasta 10 dígitos sin 0 ni 15.
* **DNI**: se valida el formato argentino (7–8 dígitos) y se guarda `Dni_Verificado = 1`; no se consulta ningún registro oficial.

## Trabajar en equipo con GitHub

```bash
git init -b main
git add .
git commit -m "ChukoStock: app PHP conectada a la base de datos"
git remote add origin https://github.com/<usuario>/<repositorio>.git
git push -u origin main
```

* Cada integrante trabaja en una rama por tarea (`git switch -c feature/nombre-tarea`) y abre un *Pull Request* hacia `main`.
* `config.local.php`, las fotos subidas y los archivos crudos de MySQL (`.frm`, `.ibd`) están en `.gitignore`: **nunca** subas contraseñas ni la carpeta `data` de MySQL.
* Para compartir datos de ejemplo: phpMyAdmin → *Exportar* → SQL, y guardalo como `sql/datos_ejemplo.sql`.
* Un workflow de GitHub Actions (`.github/workflows/php-lint.yml`) revisa la sintaxis PHP en cada push y Pull Request.
